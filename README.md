# CipherChat

一个只依赖 JDK 21 的 Java C/S 加密聊天室原型。客户端使用 Swing，服务器使用 TCP 和虚拟线程。

## 已实现

- 用户注册、登录和密码 PBKDF2 哈希存储
- 在线/离线用户列表
- 添加联系人、联系人申请、同意/拒绝
- 一对一实时聊天
- X25519 密钥协商与 AES-256-GCM 消息加密
- 离线密文保存与下次登录投递
- 服务端用户和未读消息持久化
- 自定义客户端图标

## 运行

要求：JDK 21，且 `java`、`javac`、`jar` 位于 PATH。

在本机体验时，双击根目录的 `启动客户端.cmd`。它会在 5050 端口尚未运行服务端时自动启动本机服务端，再打开客户端。

也可以分别启动服务器和客户端：

```powershell
.\scripts\start-server.ps1
```

再启动两个客户端：

```powershell
.\scripts\start-client.ps1
```

服务器可单独通过根目录的 `启动服务器.cmd` 启动。最新打包客户端位于 `dist/CipherChat-Updated/CipherChat-Updated.exe`；直接打开它时，需要先启动服务器。局域网连接时，请先在服务器电脑上运行服务端，再在客户端输入服务器电脑的局域网 IP。

分别注册两个账号即可互相聊天。默认服务器地址为 `127.0.0.1:5050`。局域网其他电脑连接时，将服务器地址改为运行服务器电脑的局域网 IP，并在防火墙中允许 TCP 5050 端口。

## 两台电脑联机

服务器只有一个。两台电脑必须连到**同一台**服务器，才能互相找到对方并加好友。

客户端程序里不含服务器，所以“两台电脑各自双击 `启动客户端.cmd`”会变成两台各跑各的服务器，账号数据彼此独立，表现为加好友提示“找不到用户”、消息发不出去。正确做法：

1. 只在 A 电脑上启动服务器：`启动服务器.cmd`（或 `.\scripts\start-server.ps1`）。首次运行 Windows 会弹防火墙提示，选择允许访问。
2. 在 A 电脑上执行 `ipconfig`，记下 `IPv4 地址`，形如 `192.168.1.23`。
3. B 电脑上用 `启动客户端.cmd` 打开客户端，把登录页的 `服务器` 改成 A 电脑的 IP，端口保持 `5050`。
4. 两台电脑分别注册**不同的**用户名，然后互加好友。

加好友的完整过程：一方点左下角 `+ 添加联系人`，输入对方用户名并确定；对方在线时会立刻弹出确认框，同意之后双方的联系人列表里才会出现彼此（未同意前列表里不会显示对方）。如果对方此刻不在线，申请由服务器保留，等对方下次登录时补弹。

左侧列表显示的是**已成为联系人**的人，不是所有注册用户；所以“列表里没有对方”和“加好友失败”是两件不同的事，前者通常是还没同意。

## 数据位置

- 服务端账户与未读密文：`data/cipherchat-state.bin`
- 客户端身份私钥：`%USERPROFILE%/.cipherchat/keys/<用户名>.properties`
- 客户端聊天记录：只存在客户端运行内存里，关闭客户端后不再保留（当前原型的已知限制）

请备份客户端私钥。删除或更换私钥后，旧离线消息无法解密。

服务端只在对方离线期间暂时保存消息密文，对方登录后被取走并删除，因此服务端不保存聊天历史。

## 安全范围

这是课程设计原型，不应直接用于真实机密通信。它展示了端到端加密的核心流程，但尚未实现成熟产品所需的身份指纹核验、前向保密、密钥轮换、多设备密钥管理、TLS 服务器认证、防重放机制和安全审计。

服务器只接收消息密文，但仍能看到账号、通信双方、在线状态、消息时间和密文长度等元数据。
